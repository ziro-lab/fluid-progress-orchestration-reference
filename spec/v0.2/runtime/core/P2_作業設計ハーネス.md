# P2_作業設計ハーネス
## FPO v0.2 / module v0.7

### 役割

current Definition、Decision Policy、外部世界を、P3が追加Design判断なく実行でき、P4がcriteria-levelで検証できるDesignへ変換する。

`WORK_DEFINITION_CONTRACT.md` のcurrent Definitionを入力とし、`EXECUTION_PLAN_CONTRACT.md` に従うExecution Planを作る。

### Design outputs

- design revision and basis refs
- stable execution step IDs and dependencies
- each step owner, inputs, outputs, adoption condition, invalidation condition
- Capability class requirements and binding constraints
- Attempt / strategy family / stop-switch conditions
- validation method and criterion mapping
- external Effect intents, classification, Approval and recovery plan
- resource envelope allocation and deadlines
- execution-time preconditions and revision checks
- cancel / resume semantics

### Re-design

checkpoint後退時も外部世界が巻き戻ったと仮定しない。
既存Artifact、Effect、Operation、Evidenceの現在状態を前提に影響範囲を決める。

Verification methodを変更する場合、旧methodに対するcoverage非低下または差分を明示し、変更後methodだけで変更自体を正当化しない。
Riskに応じて独立reviewを要求する。

### Research and Capability

J2で必要なM・Capability classを選ぶ。
Research結果やCapability提案をそのままDesign変更として扱わず、P2がDecision Policyと根拠に照らして採用する。

### checkpoint

全MUST Design判断、step、verification、適用されるEffect recovery、stop条件が確定し、valid commitへ保存された後だけ `designed` とする。

設計不能、Capability不適合、観測不能、Authority不足等はActive Blocker化する。

### 制約

実行、Target変更、criteria verdict、Acceptanceを行わない。
未解決判断が残る状態でdesignedとしない。

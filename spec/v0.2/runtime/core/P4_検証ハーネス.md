# P4_検証ハーネス
## FPO v0.2 / module v0.9

### 役割

current Validation Methodに従い、current TargetとExecutionをcriteria-levelで判定し、Evidence adoption、criteria verdict、Acceptanceを所有する。

`EXECUTION_PLAN_CONTRACT.md` に事前定義されたvalidation hook / failure routeと、`EVIDENCE_CONTRACT.md` を使用する。

### Evidence adoption

次を確認する。

- criterion / claim / object / method / environment revisionがcurrentである
- freshness、coverage、trust domain、independence basisが十分である
- contradictory / retracted / superseded Evidenceが未解決でない
- Worker自己申告だけに依存していない

各MUST criterionを `PASS / FAIL / UNKNOWN / NOT_APPLICABLE` で記録する。
UNKNOWNまたは未解決conflictが一件でもあればacceptedにしない。

### Predefined Validation failure route

P2がValidation Methodへ事前定義し、観測結果が条件へ一意に一致する場合だけ、P4は次のcheckpoint後退を適用できる。

- redefinition required → `none`
- redesign required → `defined`
- same Designの再実行 → `designed`
- Target / Design不変のvalidation repeat → `executed`

これは**決定論的なValidation route Authority**であり、原因診断や新しいRecovery strategyではない。
条件が曖昧、前提崩壊、Evidence conflict、観測不能、事前定義外の場合はActive Blocker化し、診断rollbackをP5へ返す。

### checkpoint

全MUST criteria PASS、current refs固定、Acceptance根拠がvalid commitへ保存された後だけ `accepted` とする。

### 制約

Target変更、Design変更、Verification method変更、Effect recovery、Blocker strategy決定を行わない。
事前定義のないrollbackを採用しない。

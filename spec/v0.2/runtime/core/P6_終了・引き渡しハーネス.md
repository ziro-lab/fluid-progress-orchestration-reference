# P6_終了・引き渡しハーネス
## FPO v0.2 / module v0.2

### 役割

accepted workをsettleし、最終成果・根拠・既知制限を引き渡して成功完了へ閉じる。
資産化はclosure条件に含めない。

### Completion Settlement

Machine-authoritative settlementは `record_type = terminal_settlement` として保存する。

次をすべて確認する。

- current MUST criteriaが全てPASS
- open Active Blockerがない
- inflight Delegated Operationがない
- unknown / unsettled required Effectがない
- pending pause/cancel/amendment/approval revocationがない
- current Definition / Design / Target / Evidence refsが固定されている
- final result manifestがある
- known limitations / nonblocking unresolved / operating instructionsが記録されている
- user-facing handoffが作成されている
- retention / sensitivity / redaction policyが記録されている

成立したらP6 AuthorityのCompletion Settlementをvalid commitへ含め、`checkpoint = closed` とWork Control `lifecycle = terminated / terminal_disposition = completed` を同一semantic commitでpublishする。

### Settlement failure

Settlement前提が不足・失効している場合、P6はcheckpointを直接後退させない。
不足内容、current refs、必要なowner stageをActive Blockerとして記録し、P5のdiagnostic rollbackまたはP4の事前定義Validation routeへ返す。

inflight/unknown Effect、Evidence conflict、未処理Control Event、handoff不足を成功完了として補完しない。

### Assetization

再利用資産化はoff-by-defaultであり、`extensions/assetization` のpost-actionまたは別workとして扱う。
資産化失敗は本workのclosedを取り消さない。

### 制約

新しい成果物Design、通常Target変更、Acceptance再判定を行わない。
